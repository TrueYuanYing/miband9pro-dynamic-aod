# 动态息屏的实现方法

## 目标与分工

进入真正系统 AOD 时，自动播放一次黑白动画，停在最后一帧；时间、日期和星期继续更新。不能在结束后停掉所有屏幕刷新，否则时间也会冻结。我们只暂停动画计时器，保留原厂分钟更新链。

早期 native sprite 和 Lua Image 动画都会停在首帧，而分钟变化时图像又会变化。这说明已有页面能显示并更新，但不足以证明低功耗状态持续调度了动画。通过精确 AP 的静态分析和局部指令测试，本项目定位到进入 AOD 时 UI timer 暂停、屏幕 ON 状态才安排普通 LVGL timer 的路径，以及独立的 AOD 分钟刷新链。

## 运行流程

1. 正常表盘页面先完成显示，再延迟初始化自有模块；初始化和 UI 创建分离，避免画面创建失败就阻断启动。
2. 只接受 n67cn 3.1.175 的已知指纹、堆边界、MPU/缓存条件和预期回调。保留原屏幕回调转发，不改 Flash。
3. 将本项目原生代码复制到自有、受边界检查的 RAM，经缓存发布后安装屏幕状态回调。UI线程中延迟初始化原生 timer，避免在未知上下文提前调用系统循环。
4. 在系统进入 AOD 时启动一次短时 pulse，用已有显示队列推进 Lua。原模块从100ms启动，亮屏且 ready、未播放/未 pending 时再把自有镜像调到40ms；关闭 gate，检查原100/50/40成对签名，发布缓存并读回指令别名，最后恢复 gate。失败时回滚到操作前实际值；公开版增加了跨实例隔离标记，回滚写入、缓存发布或读回没有确认成功时保持 gate 关闭，其他页面实例不能重新开启。
5. Lua 每40ms请求下一帧；PNG按透明边界裁剪，切换时同步更新原坐标加裁剪原点，避免解码大面积空画布。相同图片与坐标跳过重复设置。
6. 第68帧成功设置并请求 redraw 后，标记 `done`，原生模块停止动画 pulse，Lua暂停动画 timer。这里没有物理面板 flush ACK，不能把请求提交等同于屏幕完成显示。
7. 重新亮屏或关闭页面取消动画；下次进入 AOD 重新播放。Lua有10秒时钟异常兜底，原生有12秒硬上限，防止失败后无限唤醒。

## 关键边界

- 公开提炼版对日志/receipt 顺序、回滚和 BIN 资源判断做了额外加固，和私人 V20 的 Lua 不逐字节相同；这些改动仅经过离线故障注入测试，不能继承参考版本的实机验证结论。原始自有模块模板和偏移保持不变。
- 原生模块安装时初始 gate 为 1。公开版在取得可信 context 后先关闭 gate，再写 receipt，验收成功才重新开启。但若原生执行后 NSH 状态或 context 读回本身失败，或者后续关闭 gate 的内存写也失败，Lua 无法保证关闭模块；12秒上限仅限制单次 pulse，不证明设备整体安全。这一初始化窗口仍未消除，不能称为完全 fail-closed。

- 新模块的加载模板、入口、相对偏移和持久化目录必须保持一致。此前直接改启动模块和目录的提帧版实机失败；恢复已可用模板，再调整已就绪的自有 RAM 才重新工作。
- native timer ABI、分配/释放、执行/数据别名、缓存发布和线程上下文都依赖具体固件。换型号或换OS版本要重新分析和验证，不能只替换版本号或放宽指纹。
- 本仓库的高级打包工具要求基底已经有本项目识别的 AOD Lua host；它不是万能的表盘格式转换器。
- 普通Vela快应用的低亮度前台版本曾被探索，但不等于自动接管系统AOD，最终没有用它冒充目标效果。
- 加快帧间隔会缩短同一组帧的理想播放时间；69帧以40ms推进约2.72秒。实际设备可能更慢，当前V20没有面板FPS测量。

## 如何验证

先完成输入/包检查与 Lua/指令测试，再用保留原表盘的设备做实际加载、自动息屏、末帧保持、分钟变更、再次唤醒/息屏和退出检查。除动画外，还应核实数据源、原生跳转、连接和耗电；本项目的离线测试不能保证这些设备行为。公开结果请区分模拟、用户反馈和实测，并提供测试条件。
